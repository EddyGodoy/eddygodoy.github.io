Enhancement 2 — Algorithms and Data Structures

The reason I decided to go with this artifact was for one it was one of my more simple projects as it is one of the older ones but also seemed to have a bit more potential to it considering it was so bare bones meaning there was a lot more I could do with it especially for the algorithms and data structure portion of the project as for the most part this is all about handling and managing certain contact information data but the way that it is handled is very inefficient and the searching through potential contacts just takes way too long and relies on the code going through a-z one at a time until it finds the specific ID you chose until a match is found instead of just pulling up the actual user contact itself right from the jump. When it comes to showcasing my skills it generally just showed I could set up a simple array and add or remove data to it that I could then search linearly through the use of the unique id so to improve upon it I removed all aspects of the array list for sorting and gathering the data and instead used a HashMap to in this case be able to do specific searches or lookup specific user contact information which allows the application to now be more efficient with its data management. To do this I had to update two out of the four files with those being the ContactService file in which most of the work of the application was being done in order to go through and implement the data it was given as well as any potential changes or data being called for was all done here with the majority of the changes having to do with the array segments all having to be removed and updated to match and fit the HashMap sequences which would allow the data to be stored in memory but this time not just staying linear and being able to pull any contact instantaneously with just the contact ID. The other file changed of course was the ContactServiceTest file and this was not so much to change the code or how it works but mostly to update the tests from this application from the old array format to the newer enhanced format so that no errors would occur and all the processes could still run smoothly just under the new HashMap. With this enhancement I can showcase how I can improve the data structures that were in place in order to scale the application and make it a lot more effective without changing the fundamental objective it was created for while also providing a proper understanding of what steps I took to get there and what changes I specifically made in order to get to the enhanced version I presented.

When it comes to what I learned I realized making the changes to something I had not worked on in so long looked a lot scarier than it really was as initially I was kind of worried and concerned about the possible changes just being too much and essentially changing the program altogether yet I realized that keeping it simple yet effective was the better way to go as it just showcased enough skills for improvement rather than my ability to create something new. The only real challenges I faced here were really the different options of what changes I could make and whether or not they were enough when in reality it was a lot simpler once I made my mind up and stuck to it.

Enhancement 3 — Databases

The reason I chose this artifact for the database portion of the enhancement is because I saw that this artifact was in fact just collecting data within memory but had no real database so every time the application shuts off then the list of contacts is of course reset which is not ideal. I managed to modify two separate files again making sure to keep the core fundamentals of the actual application intact so its still the same artifact just improved upon with the two files changed being ContactService and ContactServiceTest in which I managed to move the contact information from memory to a SQLite database which would then create a database file with all the contact information data and display it no matter if the application was restarted or not. Here I also managed to create a table to display this information whenever necessary but ultimately the application itself still stores contact information still has unit testing and works as intended even still searching through the contact id, but the actual database changes allow it to permanently store this data and use or edit at any time. This inclusion of SQLite of course allows for the application to work with permanent storage now as opposed to temporary storage that only held while the application was running and active without it having to reset every time the application goes offline. Apart from that it also gives you better CRUD functionality as it allows the user better and safer database queries that were not there before allowing for the data to be created or deleted, updated or read/retrieved in a much more efficient way and with better safety parameters all around allowing for this enhancement to be a complete overhaul to the way it was managing these actions before.

The reason I decided on this exact enhancement is the fact the other course I am currently taking, which is DAD-220, gave me a bit of a refresher and some inspiration when it comes to databases as that is all I am currently working on and data being added and tables to showcase it are things I am doing basically week in and week out, something I had not really worked on much before but wanted to see just how much I was really catching on and understating so trying to implement this type of functionality into my own project was a bit of an interesting idea and just wanted to see how well I could implement these two courses together. Really that is where the inspiration came from and I just simply had to figure out the most effective way to replicate that but luckily it was quite fresh so I did not face too many challenges apart from being able to mold it all together to make it work seamlessly and a few hiccups were had a long the way but through trial and error I managed to make it all work as intended.
